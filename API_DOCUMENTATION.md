# API Documentation — Referral & Slider (for Mobile App)

Slider List (public)
- URL: GET /api/sliders
- Public endpoint (implemented in `Api\SliderController@index`). Returns only active sliders filtered by optional start/end date range and ordered by `order`.

- Behavior / date filtering:
  - Each slider has nullable `start_at` and `end_at` datetime fields.
  - A slider is returned only when `is_active = true`, `start_at` is null or `start_at <= now`, and `end_at` is null or `end_at > now`.
  - Important: when an admin enters an end **date** (e.g. `2025-12-23`) the system treats it as inclusive of that day by storing `end_at` as the start of the next day (i.e. `2025-12-24 00:00`) so the slider remains visible through the full day `2025-12-23`.

- Response (200) example:
  [
    {
      "id": 12,
      "title": "Welcome",
      "description": "Short description...",
      "image": "https://egfollow.com/storage/sliders/abcd.jpg",
      "is_active": true,
      "order": 0,
      "start_at": "2025-12-20T00:00:00Z",    # nullable
      "end_at": "2025-12-24T00:00:00Z"       # exclusive upper bound
    },
    ...
  ]

Notes about slider `image` field:
- Images are returned as fully-qualified public URLs (asset("storage/...")) when stored via the admin.
- Ensure `php artisan storage:link` has been run on the server so URLs like `/storage/...` are publicly accessible.

Apply Referral Code (authenticated)
- URL: POST /api/user/apply-referral
- Auth: Required (Bearer token)
- Payload (JSON):
  - code (string) — the invitation/referral code to apply
- Behavior:
  - Each user can apply a referral code only once (the code application is recorded in `user_referrals`).
  - If the code is valid and the user hasn't used a code before, the configured `referral_points` (admin setting) are added to the applying user's `points`.
  - The API will not allow using your own code.
- Success Response (200):
  {
    "added_points": 50,
    "total_points": 125
  }
- Error responses:
  - 400: Referral code already used by this user, or trying to use own code.
  - 404: Invalid referral code.
  - 500: Server error applying the code.

Example cURL — Apply referral
```bash
curl -X POST "https://egfollow.com/api/user/apply-referral" \
  -H "Authorization: Bearer <token>" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"code":"ABC123"}'
```

Example cURL — Get sliders
```bash
curl -X GET "https://egfollow.com/api/sliders" -H "Accept: application/json"
```

Get Authenticated User's Referral Code
- URL: GET /api/user/referral-code
- Auth: Required (Bearer token)
- Description: Returns the current authenticated user's invitation/referral code. If the user does not yet have a code, the server will generate a unique uppercase code, save it to the user's record, and return it.
- Response (200):
  {
    "code": "ABC12345"
  }
- Error: 401 if the user is not authenticated.

Example cURL — Get referral code
```bash
curl -X GET "https://egfollow.com/api/user/referral-code" \
  -H "Authorization: Bearer <token>" \
  -H "Accept: application/json"
```

Notes for mobile developers
- Always include `Accept: application/json` in requests to receive JSON errors/responses.
- On auth-protected endpoints, use the Bearer token returned from `/api/login` or `/api/register`.
- The app's `points` will be returned in some endpoints (e.g., `GET /api/user` when authenticated, or in the response to applying referral). Check `/api/user` for the current authenticated user data.

Admin settings that affect behavior
- `referral_points` — the number of points awarded when a referral code is successfully applied. Admins can change it via the admin UI (Settings page).
- `points_per_ads` — points awarded for viewing ads.
- `ads_per_user_per_day` — day limit for ad-point awarding.
